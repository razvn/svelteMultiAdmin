Kubernetes

deploy/kubernetes holds a ready manifest and a walkthrough. One pod runs the portal and both apps. The apps find the databases of every review namespace (one per merge request, for example), connect with the password from that namespace's Secret, and let Kubernetes RBAC decide who may use which one; the portal decides who may open which app at all.

Object Purpose
Namespace tools, ServiceAccount Where the portal runs.
ClusterRoleBinding to system:auth-delegator SubjectAccessReviews: "may this person use the database of that namespace?"
ClusterRole and binding multiadmin-discovery List namespaces and Services, and read only the Secrets named redis-auth and mysql-auth.
Secret multiadmin The portal config (it holds the cookie secret) and the bootstrap password.
ConfigMap multiadmin-apps The apps' own configs: discovery of review namespaces, audit log to stdout.
PersistentVolumeClaim users.json of the local accounts.
Deployment One replica, Recreate, non-root, readiness probe on /api/health.
Service and Ingress ClusterIP behind an Ingress with three hosts.

Try it locally

docker build -t multiadmin:dev .
kubectl apply -f deploy/kubernetes/multiadmin.yaml
kubectl -n tools rollout status deploy/multiadmin
kubectl -n tools port-forward svc/multiadmin 8080:80

Open http://portal.localhost:8080 and sign in as admin with the bootstrap password of the Secret. A browser does not send x-forwarded-proto, so add it with a request-header extension on *.localhost, or use an Ingress controller with a certificate.

Kubernetes access checks

Discovered servers carry a namespace, and the apps ask the API server whether the person may use it. The person is the user name and the groups the portal forwards (for OIDC and trusted-header sign-in), with the prefixes you configure in authorize (userPrefix, groupsPrefix). They must equal the API server's --oidc-username-prefix and --oidc-groups-prefix, or RBAC denies everyone. The apps' own guides cover discovery, selectors, secrets and troubleshooting in full: svelteRedisAdmin and svelteMyAdmin.

Going to production

  • Change every secret and keep the apps' config in a Secret too if it holds static servers with passwords.
  • Set the three publicUrl values and the Ingress hosts; the Ingress must send x-forwarded-proto and x-forwarded-host.
  • Switch auth to oidc, or to trusted-header behind oauth2-proxy with trustedProxies set to its addresses. With an SSO proxy add its auth-url and auth-signin annotations to the Ingress.
  • The ClusterRoleBinding lets the portal read redis-auth and mysql-auth in every namespace. To narrow it, bind multiadmin-discovery with a RoleBinding per review namespace from the pipeline that creates it.
  • Push the image to your registry and drop imagePullPolicy: Never.
